Networking Concepts

This page explains how networking makes our website work by connecting various concepts to our actual deployment on Netlify.

DNS (Domain Name System)

DNS is the system that translates human-readable domain names into IP addresses. Here's how our website uses DNS:

How DNS Works for Our Project

  1. You type csc6220project1.netlify.app into your browser
  2. Your browser sends a DNS query to a DNS resolver (usually provided by your Internet Service Provider)
  3. The DNS resolver finds the A record for our domain, which points to Netlify's servers
  4. Netlify's DNS server responds with the IP address(es) that host our site
  5. Your browser connects to that IP address to retrieve our website

DNS Records in Our Configuration

Netlify uses multiple types of DNS records to route traffic efficiently:

  • A Records (IPv4): Point our domain to Netlify's CDN servers with IPv4 addresses
  • AAAA Records (IPv6): Provide the same routing but for IPv6-capable clients
  • CNAME Records: Our custom domain configuration uses CNAME records to point to Netlify's servers

Without DNS, we would need to remember IP addresses instead of domain names—imagine visiting 18.208.88.157 instead of csc6220project1.netlify.app!

IP Addressing

IP addresses are the numerical identifiers that uniquely identify our website on the internet. Our domain resolves to multiple IP addresses for redundancy and performance through load balancing.

Why Multiple IP Addresses?

Netlify uses a global Content Delivery Network (CDN) with multiple server locations to:

  • Improve Performance: Servers in different geographic regions provide faster content delivery by serving users from locations closer to them
  • Ensure Reliability: If one server goes down, traffic can be rerouted to another
  • Handle Traffic Spikes: Multiple servers can distribute the load when many users access the site simultaneously

Our Domain's IP Addresses

IPv6 Addresses (128-bit):

Note: IPv6 uses hexadecimal notation and provides significantly more addresses than IPv4 (2^128 vs 2^32). Netlify supports both for maximum compatibility and future-proofing across all modern browsers and devices.

Protocols

HTTPS: Secure Data Transmission

Our website is served over HTTPS (Hypertext Transfer Protocol Secure), which encrypts all communication between your browser and our server using TLS (Transport Layer Security).

Why HTTPS matters:

  • Encryption: All data sent between your browser and our server is encrypted, preventing eavesdropping
  • Authentication: TLS certificates verify that you're connecting to the legitimate Netlify server hosting our site, not an impostor
  • Integrity: Ensures that data hasn't been tampered with during transmission
  • Browser Trust: Modern browsers show a lock icon in the address bar, indicating a secure connection

Netlify automatically provides HTTPS for all hosted websites using SSL/TLS certificates (issued through Let's Encrypt and their partners), ensuring our site is secure by default and requires no additional configuration.

HTTP Status Codes

HTTP status codes inform the browser about the result of each request. Here are the main codes relevant to our website:

  • 200 OK: The request was successful. The server is returning the requested resource (index.html, style.css, etc.)
  • 304 Not Modified: The resource hasn't changed since it was last cached. The browser can use its cached copy
  • 404 Not Found: The requested page does not exist on our server
  • 500 Server Error: An unexpected error occurred on the server

HTTP/2 Protocol

Our site uses HTTP/2, which is more efficient than HTTP/1.1. HTTP/2 allows multiple files to be requested simultaneously over a single connection, reducing load time and improving performance.

Request/Response Headers

Headers are metadata that provide crucial information about the request and response. Here's an example of the actual headers when accessing our Netlify-hosted site:

Response Headers:
HTTP/2 200 OK
server: Netlify
content-type: text/html; charset=utf-8
content-length: 3125
last-modified: Wed, 04 Mar 2026 15:22:14 GMT
cache-control: public, max-age=3600
age: 240
x-netlify-request-id: a1b2c3d4e5f6g7h8
x-frame-options: SAMEORIGIN
x-xss-protection: 1; mode=block
strict-transport-security: max-age=31536000; includeSubdomains; preload

What These Headers Mean

  • content-type: Tells the browser that this is HTML encoded in UTF-8
  • last-modified: When this file was last updated on the server
  • cache-control: Instructs the browser to cache this page for up to 600 seconds (10 minutes)
  • age: How long this content has been cached (120 seconds old)
  • strict-transport-security: Forces HTTPS connections, preventing downgrade attacks
  • x-frame-options: Prevents this page from being embedded in an iframe, protecting against clickjacking attacks

How This All Works Together

  1. Your browser makes a request for csc6220project1.netlify.app
  2. DNS resolves this domain to one of Netlify's CDN IP addresses
  3. Your browser establishes an HTTPS connection using TLS encryption
  4. The HTTP/2 protocol efficiently sends your request to Netlify's servers
  5. The server responds with a 200 status code and sends back our HTML page with all relevant headers
  6. Your browser caches the page according to the cache-control headers set by Netlify
  7. The page is rendered securely in your browser with the Netlify edge network ensuring fast delivery globally
